def column_group(name):
    if name.startswith('Company_'):
        return 'کارفرما'
    if name in {'ad_id', 'release_month', 'Jobpost_ActivationTime_YEAR_MONTH'}:
        return 'شناسه و زمان'
    if name in {'Jobpost_MinSalary', 'Jobpost_MaxSalary', 'Jobpost_SalaryCanBeShown'}:
        return 'حقوق'
    if name in {'Jobpost_SoftwareSkills', 'Jobpost_LanguageSkills', 'Jobpost_AcademicFields'}:
        return 'مهارت و تحصیلات'
    if name in {'Jobpost_BenefitFa', 'Jobpost_BenefitEn'}:
        return 'مزایا'
    return 'مشخصات آگهی'

Reading table 4.3 and figure 4.1: missingness follows a structural pattern, not a random one. Three “optional” data columns are almost always empty: disability support (95.1%), secondary job categories (77.7%) and language skills (64.5%). In contrast, the core posting columns — title, job category, province, work type, experience and company size — have no missing values. This means the core of the data is reliable and the gaps belong to supplementary layers (skills, benefits, age).

Salary is also 66.9% missing, but this missingness is not of the “unrecorded” kind; the posting has not officially declared salary. The difference between the two is examined in section 9.

Reading table 4.4 and figure 4.2: most rows have between 3 and 7 empty cells and the median missingness per row is 5 cells. Only 209 postings (0.1%) are completely full, and 17.5% of rows have 10 or more empty cells. This distribution shows that dropping incomplete rows would destroy a large part of the data; therefore the right strategy is not to drop and to analyze each indicator on the sample available for it.

Reading tables 4.5 and 4.6: the data is structurally clean: no fully duplicated rows, no duplicate identifiers and no inconsistent salary ranges (minimum greater than maximum). The match between the disclosure flag and the presence of a salary value is also complete: wherever SalaryCanBeShown=True, both ends of the range are filled, and wherever it is False, both are empty. Therefore “missing salary” in this data is not a recording defect; it is a deliberate employer choice not to disclose. This very fact makes the analysis in section 9 necessary.

Key figures: cardinality

  • Unique job titles: 68,711
  • Unique working-hours descriptions: 68,247
  • Unique software skill combinations: 49,115
  • Main job category / industry: 77 / 44

Reading table 4.8: two different worlds sit side by side in this data. The managerial columns (job category, industry, province, work type, company size) have low, controlled cardinality and are ready for grouping. In contrast, the free texts are highly varied: 68,711 job titles, 68,247 working-hours descriptions and 49,115 unique software skill combinations. Almost every posting has its own working-hours description; so extracting features from this text is a mandatory step, not an optional one.

3,561 different industry combinations for companies also show that company industry is multi-valued and must be processed as a list, not as a single label.
